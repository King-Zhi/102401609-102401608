## 2026-10-07：修复搜索高亮与日期校验

分支：`search-date-fix`。基于 PR #3 的改动继续完善，合并时应先处理 PR #3。

### 搜索高亮

- 问题：原实现先转义再搜索。例如原文 `&` 变为 `&amp;`，搜索 `&` 会拆开实体；搜索原文中不存在的 `amp` 却会错误高亮。搜索完整的 `<script>` 也无法正确匹配原文。
- 修改：先在原文定位所有匹配，再分别转义普通片段和匹配片段，最后为匹配片段包上固定的 `<mark>` 标签。
- 保留原有大小写不敏感、关键词首尾空格处理和全部匹配高亮；正则符号仍按普通文字匹配，不作为正则表达式执行。
- 新增测试覆盖 `&`、尖括号、单双引号、实体名称误匹配、`C++`、括号、反斜杠、重复匹配及完整标签转义。

### 日期校验

- 问题：只使用 `Date.parse` 不能严格验证日历日期，部分不存在的日期会被自动进位；原来没有拦截未来日期。
- 修改：限定 `YYYY-MM-DD` 格式，解析后回查年月日，拒绝不存在的日期、年月日越界和零年，并限制遗失或拾获日期不晚于本地今天。
- 默认日期原来使用 `toISOString()` 截断，得到 UTC 日期，在中国凌晨可能显示为前一天。新增本地日期格式化方法，用于默认日期和日期选择器上限。
- 日期选择器限制最大日期，发布、编辑和编辑的数据层仍执行统一校验；日期框获得焦点时重新计算上限，适应页面跨午夜打开的情况。
- 新增测试覆盖正常月末、闰年、世纪闰年、非法格式、今天与明天、本地凌晨和跨年，以及编辑失败时原数据不被覆盖。

### 验证记录

- 先添加回归用例，在旧实现上得到 29/38 通过、9 项失败，复现了问题。
- 修复后 38/38 通过，浏览器测试页和 Node.js 的结果一致；Node.js 分别在 `Asia/Shanghai`、`America/Los_Angeles`、`UTC` 时区运行，均为 38/38 通过。
- 浏览器发布测试标题 `C++ & <卡套> "蓝色"`，确认未来日期会被表单拦截且输入保留，改为当天可成功发布。搜索 `&` 时标题和地点里的两个匹配均正确高亮，页面文字完整。
- 浏览器曾加载旧脚本缓存，换用新的本地测试地址后确认执行的是新版本；没有把缓存下的旧结果作为修复后的结果。
- 已更新 `test/test_result.png`；特殊字符搜索截图保存在 `docs/images/search-special-characters.png`。

## 2026-10-07：完善图片上传与重复提交防护

本次改动暂留在本地 `upload-submit-fix` 分支，按要求等待通知后再推送和创建 PR。

### 图片上传

- 问题：原来超过 2MB 只弹出提醒，仍会继续读取；文件选择范围过宽，没有处理损坏图片和读取失败。
- 修改：限定 PNG、JPG、JPEG、WEBP，同时检查 MIME、扩展名、非空及 2MB 上限。先读取再解码，确认图片尺寸有效后才替换预览；失败时保留原图并恢复提交按钮。
- 修改：连续选图、移除图片或关闭表单时使旧请求失效，防止迟到的读取或解码回调覆盖最新状态。

### 重复提交与记录 ID

- 问题：提交期间没有保护，时间戳 ID 在同一毫秒发布多条记录时可能冲突。
- 修改：读取图片或保存时禁用提交按钮并更新提示；提交中不重复处理，表单成功关闭后忽略后续提交。通过 `finally` 释放保存锁，失败保留输入，便于重试。
- 修改：新 ID 从当前毫秒开始，遇到已存在 ID 时递增避让，发布时间仍使用原时间戳。没有禁止内容相同的合法再次发布。

### 验证记录

- 核心测试从 38 项增加到 43 项，新增图片格式、大小、字段、大小写和同毫秒 ID 冲突测试。
- 增加 14 项页面逻辑测试，通过模拟 DOM、读取器和图片对象执行实际页面方法，检查损坏图片、异步回调顺序、关闭、移除、读取中提交、重复提交、失败重试和异常释放锁。
- Node.js 运行结果：核心测试 43/43，页面逻辑测试 14/14 通过；浏览器核心测试页同样为 43/43 通过。
- 实际浏览器使用正常 PNG 验证解码与预览，再选择 4,437,841 字节的 PNG，确认超过 2MB 时拒绝且原预览保留。选择仅含文字的损坏 PNG，确认解码失败提示、原预览和可重试状态。

## 2026-10-08：支持校园简称与子序列智能模糊检索与高亮

对应提交：`feat(search): 支持校园简称与子序列智能模糊匹配与高亮`。
负责成员：成员一（学号 102401609）。

- **问题**：原搜索仅支持严格子字符串连续包含，用户搜索常用课目简称如“高数”时无法检索到《高等数学第七版》，搜索“饭卡”无法匹配“学生卡”，缺乏贴近大学生日常搜索习惯的容错与联想能力。
- **修改**：
  1. 在 `js/utils.js` 中新增 `matchKeyword` 智能模糊检索算法：优先执行精准连续包含；其次引入校园专属常用简称与近义词库（如“高数”关联“高等数学/数学”，“线代”关联“线性代数”，“饭卡/一卡通”关联“校园卡/学生卡”等）；最后执行字符子序列模糊匹配（每个字符按序在原文中出现即可命中，如“操场钥匙”命中“风雨操场草坪遗落一串宿舍钥匙”）。
  2. 升级 `highlightKeyword` 高亮算法：当触发子序列模糊匹配时，智能在原文中准确定位并分别高亮命中的字符（如在“高等数学”中精准高亮“高”和“数”），同时严格保留 HTML 实体防 XSS 转义。
- **测试与验证**：
  - 新增测试用例 44（校园常用简称与子序列模糊匹配检索，验证“高数”、“饭卡”、“操场钥匙”）；
  - 新增测试用例 45（子序列模糊匹配精准字符高亮与防 XSS 渲染）；
  - 全套 45 项自动化单元测试在 Node.js 和浏览器测试运行器中均实现 100% 全部通过（45/45 PASS）。

## 2026-10-08：修复未传实物图片误套用示例图缺陷，增加无图优雅占位

对应提交：`fix(image): 修复未上传图片时误套用其他物品示例图问题，增加暂无图片优雅占位`。
负责成员：成员一（学号 102401609）。

- **问题**：用户发布新物品时若未上传实物照片（如发布一部遗失的“手机”），系统在表单提交阶段执行了 `itemPayload.img = itemPayload.img || this.getDefaultImageForCategory(category)`，将“数码电子”分类预设的示例图（皮卡丘 AirPods）强行赋给该手机；且卡片与详情弹窗在无图时均回退至校园卡示例图，导致用户发布内容与展示图片完全错位。
- **原因剖析**：
  1. `js/app.js` 的 `handlePublishSubmit` 中存在不合理的默认图片回退逻辑，忽视了“实物照片为选填项，未传图应真实呈现无图状态”的产品交互逻辑；
  2. 卡片渲染函数 `renderItemCard` 与详情弹窗 `openDetail` 缺乏针对无实物图片的空状态 UI，均生硬回退展示第一张预设示例图。
- **修改与优化**：
  1. **发布逻辑修正**：在 `js/app.js` 中移除表单提交时的强行占位赋值，用户未选图时严格保持 `itemPayload.img = ''`；
  2. **优雅无图占位设计**：在卡片列表与详情模态框中设计了极简美观的“暂无实物图片 / 发布者未上传照片”微质感占位块（含相机图标与规范说明），替代突兀错乱的虚假配图；
  3. **数据升级与预设隔离（精准区分预设数据与用户自发数据）**：
     - 在 `js/data.js` 的自动升级中，限定预设示例物品（ID 范围在 1001~1006 内）在未被编辑时始终维持官方高清配图（避免 1001 学生卡与 1004 钥匙因带有 `isMine: true` 测试标记被误清空图片）；
     - 仅对用户新创建的记录（`!PRESET_IDS.includes(it.id)`）清洗误存的示例图，同时兼容未编辑状态判断（`!it.updatedAt`），保护单元测试 16（显式置空并编辑保护）；
  4. **CSS 显隐加固**：在 `css/style.css` 显式增加 `.hidden { display: none !important; }`，杜绝 Tailwind 类名层级在不同场景下的潜在样式冲突。
- **测试与验证**：
  - 新增测试用例 46（用户新发布物品未上传图片时应保留空字符串，不误赋预设示例图且历史误赋数据自动修复，同时验证预设物品 1001 与 1004 高清图完整无损）；
  - 在 `test/app_tests.js` 中增加未传图提交场景校验用例；
  - 经验证，46 项核心单元测试与 15 项页面逻辑测试全部 100% 通过（46/46 PASS，15/15 PASS）。
